# Changelog — Comiqueta

All notable changes to this project. Governed by [`conductor/rules/CORE_RULES.md`](conductor/rules/CORE_RULES.md) — one line per work unit (not per commit), appended to `## Unreleased` in the same turn the work lands:

```
- Categoria: descrição completa (CÓDIGO)
```

The category is a concise Portuguese label (e.g. `Testado:`, `Corrigido:`, `Planejado:`, `Adicionado:`). Omit the `(CÓDIGO)` suffix when no ticket exists. Entries are consecutive — no blank line between them. On a release cut, retitle `## Unreleased` to `## [X.Y.Z] YYYY-MM-DD` and add a fresh empty `## Unreleased` above it.

> History before 2026-07-21 lives in git only — this file starts here.

## Unreleased

- Regra: formato de entrada do changelog sincronizado nos três repositórios — categoria em português, uma linha física por item, sem linhas em branco entre entradas, cabeçalho de release `## [X.Y.Z] YYYY-MM-DD` (CORE_RULES §14)

- **Antigravity hooks exist but stay off.** `.agents/hooks.json` ships `"enabled": false` with guessed `run_command` / `write_to_file` matchers; the scripts now accept those names. T7 Gradle-detection draft is in `conductor/analysis/`; not filed; no score exclusions

Reviewing every existing interface against it is KI-TBD #9; the review lists each interface with its implementations and a verdict, and shows that list before any code changes
- **The AI surface follows Antigravity's own layout.** Skills moved from `conductor/skills/`, where Antigravity never discovered them, to `.agents/skills/<name>/SKILL.md`; every rule that binds at a recognisable moment became a skill (`logging`, `strings`, `tapguard`, `ki-sync`, `planning`, `models` and the rest), `.agents/rules/` keeps only always-on and file-anchored rules, and session handoff and bootstrap are the `handoff` and `initialize` skills. The new `planning` skill carries every rule for writing a plan or synthesising a META_PLANNING, for any planning request in the chat. File names are identifiers with one convention (DOC_GOVERNANCE §18.2): `AI_BEHAVIOR.md` and `ARCHITECTURE.md` in caps, and each workflow shares one lowercase-hyphen name with its slash command (`/remove-filter`, `/update-kis`, `/rules-status`, `/token-audit`). `AGENTS.md` opens with numbered critical rules naming the skill each one triggers
- **Four unit-test suites had not compiled for some time and so ran zero assertions.** `LoadCategoriesUseCaseTest` still mocked the Room `CategoryEntity` after the contract moved to the domain `Category`; `GetPaginatedComicsUseCaseTest` still built `Comic` with `Uri` paths after they became `String`; `SettingsViewModelTest` stubbed `IGetRelevantOsPermissionsUseCase` as returning a `Flow` when it returns a plain `List`; `HomeViewModelTest` was written against MockK, which is not in the version catalogue. All four rewritten against the current signatures — 30 unit tests now run and pass across `:core`, `:feature-home`, `:feature-settings` and `:feature-viewer` (`CORE_RULES.md` §12)
- Three of those suites also mis-wired `kotlinx-coroutines-test`: `Dispatchers.setMain(dispatcher)` in `@Before` paired with a bare `runTest {}`, which gives the ViewModel and the test two unrelated schedulers, so `advanceUntilIdle()` never ran the `init` coroutines it was waiting on. Each now passes the dispatcher into `runTest`
- `:feature-settings` and `:feature-viewer` declared only JUnit for unit tests, so Truth, Mockito and `coroutines-test` resolved nowhere and neither suite could have compiled even after the signature fixes
- The library convention plugin now sets `unitTests.isReturnDefaultValues` and `isIncludeAndroidResources`. Without the first, every UI-state default that reads an Android member throws "not mocked" against the stub `android.jar` and the suites cannot start at all
- Robolectric added to the catalogue for `:feature-viewer` alone. `ViewerUIState` defaults `comicPath` to `Uri.EMPTY`, which the mockable `android.jar` leaves null (its `<clinit>` is stripped to a bare `return`), and Kotlin emits a non-null assertion on it — so the state cannot be constructed on a plain JVM. `:feature-settings` deliberately stays on plain JUnit; it only reaches Android through `ContextCompat`, which falls through to `Context.checkPermission` and is answerable by a mock
- **Release-build error logs contained nothing but their own tag.** `CrashReportingTree` called `Timber.log(priority, tag, message, t)`, which binds to `log(priority, message, vararg args)` — so the tag was logged *as* the message and the real text and stack trace were passed as format arguments no specifier consumed, then discarded. It also dropped `logI`/`logW`, which `LOGGING_RULES.md` §8.6 lists as mandatory-surviving, and never reached Crashlytics despite its name
- **17 log sites across 6 files leaked personal data into release captures** — raw SAF URIs, filesystem paths and file names, and a comic library path routinely contains the device owner's real name (§8.3). All now go through the new `LogRedaction`
- The SAF `takePersistableUriPermission`/release outcome logged at `logD`, so it never survived into a release capture even though §8.6 names it explicitly. Promoted to `logI`, with the folder count alongside
- Long log messages are split rather than silently truncated at the ~4 KB logcat byte cap, and every piece repeats its `[Comiqueta][…]` filter so a `grep` returns the whole message (`LogChunker`, §8.7). Timber's own splitter counts characters and drops the filter, so it could not do this
- The keyboard helpers swallowed the "no Activity window" branch in silence; it is now a `logW` under the new `[Comiqueta][Ime]` filter
- **Twelve deprecations replaced with current APIs rather than suppressed:** AdMob's int child-directed/under-age pair → `setAgeRestrictedTreatment`; the deprecated anchored adaptive banner → `getLargeAnchoredAdaptiveBannerAdSize`; `Icons.Filled.LibraryBooks`/`MenuBook` → `AutoMirrored`; `hiltViewModel` → its new package; `Paint.asFrameworkPaint()` → `nativePaint`; `InputMethodManager.SHOW_IMPLICIT` → `WindowCompat.getInsetsController`
- Three blanket `@file:Suppress("DEPRECATION")` removed — two masked nothing, the third hid the IME deprecation above. Dead `Context.tamanhoDaTela()`/`Size` deleted: unreferenced, and its only purpose was a deprecated `defaultDisplay.getMetrics()` call

- Rule set restructured — split `CORE_RULES.md` by topic into `PLANNING_RULES.md`, `LOGGING_RULES.md`, `UI_RULES.md` and `DOC_GOVERNANCE.md` behind a master numeric index; added log-level policy, reference-document ownership, rule placement, agent-surface parity and single-activation rules; added `.agent/` rule pointers and workflows for Antigravity; `plannings/archived/` is now version-controlled
